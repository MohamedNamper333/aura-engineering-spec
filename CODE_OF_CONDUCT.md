# Code of Conduct

The AURA Engineering Specification repository exists to support serious engineering work. We expect all contributors to communicate professionally, respectfully, and with technical precision.

This Code of Conduct applies to all repository interactions, including issues, pull requests, reviews, documentation edits, AI-assisted contributions, and maintainer discussions.

---

# 1. Purpose

The purpose of this Code of Conduct is to maintain a productive, respectful, and technically focused environment for everyone contributing to the AURA Engineering Specification repository.

We want contributions to be:

- Constructive
- Respectful
- Clear
- Evidence-based
- Reviewable
- Safe for human and AI collaboration

---

# 2. Our Commitment

We are committed to providing a collaboration environment that is free from harassment, discrimination, intimidation, and disruptive behavior.

We also commit to maintaining a repository culture where technical disagreement is handled with clarity and professionalism.

---

# 3. Core Values

Contributors are expected to act according to the following values:

- Respect for people and ideas
- Technical honesty
- Responsibility for the quality of contributions
- Transparency in communication
- Collaboration over ego
- Precision over vague claims
- Safety over convenience when handling sensitive material

---

# 4. Expected Behavior

Examples of expected behavior include:

- Using respectful language
- Critiquing ideas rather than people
- Asking for clarification when requirements are unclear
- Supporting claims with evidence, documentation, or reasoning
- Keeping discussions relevant to the repository
- Following the documented engineering process
- Treating AI-assisted content as something that still requires review

---

# 5. Unacceptable Behavior

The following behaviors are not acceptable in this repository:

- Harassment or personal attacks
- Discriminatory language or behavior
- Trolling, baiting, or deliberate disruption
- Threats or intimidation
- Deliberate misinformation
- Repeatedly ignoring repository rules
- Posting confidential or sensitive information in public channels
- Using AI to generate deceptive, unsafe, or abusive content
- Dismissing technical feedback in bad faith

---

# 6. Professional Communication

Contributors should communicate with clarity and discipline.

This means:

- Be direct
- Be specific
- Avoid emotional escalation
- Avoid sarcasm when it may be interpreted as hostility
- Avoid vague criticism without explanation
- Focus on the technical issue at hand

Disagreement is allowed. Disrespect is not.

---

# 7. AI-Assisted Contributions

AI-assisted contributions are allowed, but they must follow the same behavioral expectations as human contributions.

AI-generated content must:

- Be reviewed by a human contributor before merge
- Follow repository standards
- Avoid inventing business rules or architecture decisions
- Avoid exposing secrets, private data, or unsafe guidance
- Avoid hostile, manipulative, or discriminatory language

The human contributor remains responsible for the final submission, even if the content was generated or revised with AI assistance.

---

# 8. Maintainer Responsibilities

Maintainers are responsible for:

- Enforcing this Code of Conduct fairly
- Responding to issues in a timely manner
- Communicating clearly and respectfully
- Applying repository rules consistently
- Protecting contributors from abusive behavior
- Preserving the technical quality of the repository

Maintainers should model the same professionalism expected from contributors.

---

# 9. Scope

This Code of Conduct applies to:

- Repository issues
- Pull requests
- Code review discussions
- Documentation discussions
- Maintainer conversations related to the repository
- Any AI-assisted contribution process used for this repository

---

# 10. Reporting Issues

If you experience or observe behavior that violates this Code of Conduct, report it through the repository's maintainers or the designated private reporting channel.

Please include:

- A description of the issue
- The people or files involved, if relevant
- The date and time, if relevant
- Any supporting context
- Why the behavior is concerning

Reports should be made in good faith.

---

# 11. Enforcement Process

When a report is received, maintainers may take one or more of the following steps depending on severity and context:

1. Request clarification
2. Issue a warning
3. Request a correction or apology
4. Restrict participation temporarily
5. Remove or ignore abusive content
6. Escalate the matter internally if needed
7. Block further contributions from a user if necessary

The goal of enforcement is to protect the repository and its contributors, not to punish constructive disagreement.

---

# 12. Community Impact Guidelines

When evaluating behavior, maintainers should consider:

- The severity of the issue
- The impact on contributors
- Whether the behavior was repeated
- Whether the behavior shows willingness to correct course
- Whether the behavior affects repository safety or trust

---

# 13. Privacy

Do not share private, personal, confidential, or sensitive information in repository discussions unless it is necessary and appropriate for the issue being handled.

Do not post secrets, credentials, private keys, student data, payment details, or other sensitive material.

If such content is discovered, it should be removed and handled as a security matter.

---

# 14. Attribution

This repository's Code of Conduct is inspired by widely used open-source community standards, but it has been tailored for the AURA Engineering Specification repository and its AI-assisted engineering workflow.

---

# 15. Questions

If you are unsure whether a behavior or contribution is appropriate, ask a maintainer before proceeding.

When in doubt, choose the safer and more respectful path.
